# A2 SPI-NAND 读路径（task-50，2026-11-21）

本文件记录 task-50 的交付：给 E2631 的最小 U-Boot 增加 SPI-NAND 读路径，作为后续
「槽位感知启动」（A3/B1）的地基。**A2 只读：不写 flash、不存 env、不改 bootm；真机会话
只执行 mtd list / mtd read。**构建全部在 GitHub Actions 完成（本机不编译）。

## 1. 目标与边界

- 目标：U-Boot 能在 RAM 中运行后，通过 DM SPI + spi-mem + spi-nand 读到板载 SPI-NAND，
  用内置 mtd 命令列出并读出内容。
- 缺口：U-Boot 2027.01-rc2 已自带 spi-nand 核心、FORESEE F35SQA001G 芯片表、env-mtd；
  唯一缺的是 ZX279128S 的 SPIFC 控制器（0x94406000）驱动。
- 边界：只新增 patch 0005；patch 0001-0004 未改；firmware.yml / 主 check.yml 未改；
  无 release、无 flash 写入、kit main 未动。

设计要点（详见 uboot-port/a2-spi-nand-design.md）：

- 从内核 target/linux/zx279128/files/drivers/spi/spi-zx.c 移植，只保留 PIO 路径；
  无 DMA、无 IRQ、无 reset、不主动改控制器时钟——secondboot 已把控制器带起来，
  U-Boot 侧没有 ZX CRPM 时钟驱动，DT 故意不写 clocks，驱动仅在存在时钟时 set_rate。
- 只实现 mem_ops.exec_op + adjust_op_size + supports_op：U-Boot spi-mem 在控制器
  没有 dirmap 回调时自动回落 nodirmap 模式，直接调 exec_op。
- FIFO 搬运用「按字数 + 尾部 memcpy」处理，避免内核版按字对齐读会多读 1 字节
  SET_FEATURE 缓冲的问题。
- 保持 on-die ECC 开启（与内核 MTD 视角一致），不做裸页读。

## 6. 剩余风险与下一步

- 控制器时钟/门控状态未知（中等风险）：驱动不初始化时钟，依赖 secondboot/vendor
  U-Boot 留下的分频；若真机读到全 0 或 ID 错，先按设计文档第 9 节用 md.l 0x94406000 8
  观察控制器寄存器，再决定是否补最小时钟初始化。
- 芯片型号：实测 READID 为 FORESEE 0xCD/0x71（F35SQA001G），而内核 DTS 注释写
  HYF1GQ4UTACAE；U-Boot 侧以实测 ID 为准，两处注释差异留待 A3 统一。
- 下一步（需用户单独批准）：A2 真机会话——tftp 载入 + go 后执行 mtd list 与
  mtd read，与已知 mtd0 头部比对；全程禁止 mtd write/erase/nand write/saveenv。
  之后才是 B1（env 块）与 A3（写 mtd0 的持久化启动链）。
