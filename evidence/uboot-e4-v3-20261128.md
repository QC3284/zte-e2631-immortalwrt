## 2. 契约映射与实现要点

- **`/sysinfo`**：键序固定（result/version/banner/build/board/soc/cpu/dram/dram_mb/mtd0/spi 六项/spi_id/CP15 七项/
  九项时钟/cpu_mhz/cpu_mhz_source）。CP15 读取复用 `e2631soc.c` 的 helper（MIDR 新增读取），SPI-NAND id 取
  `mtd_to_spinand(mtd)->id.data[5]`；`cpu_mhz=1000`、`source=known`（secondboot 固定 A9 1 GHz）。失败 500，
  不写 flash/env，幂等无缓存。
- **`/log`**：`do_e2631rescue()` 在打印 banner 前把 console record ring 读成最多 16,384 B 的静态快照并记录
  `log_bytes`/溢出标志；`GET /log` body 是原始文本行，头带 `X-E2631-Log-Bytes`/`X-E2631-Log-Overflow`/`Content-Length`，
  `?download=1` 加 `Content-Disposition`；快照只做一次，之后不再读 ring。
- **`/integrity`**：空 body（Content-Length≠0 → 400 `bad body`）；16 KiB 分块只读 mtd0 `0x20000..0xC0000`，
  同一遍算 CRC32 与 SHA-256；`expect` 从 query 或 `X-E2631-Expected-Sha256` 取（query 优先，必须 64 hex，否则 400
  `bad sha256`），返回 `match=ok|mismatch|absent` 与规范化 `expected=`；GET 405、写任务/备份期间 409、读失败 500。
- **`/backup` 扩展**：在 v2.1 五分区之上加 `slot0` `0x00700000`/`slot1` `0x02300000`（各 `0x1C00000`）、
  `rootfs`（按 `next_slot`：slot0 → `0x00B00000`，slot1 → `0x02700000`，`0x1100000`）、`header`（slot0 →
  `0x01C00000`，slot1 → `0x03800000`，`0x20000`）；沿用 v2.1 响应头。整槽用 1 MiB `malloc_cache_aligned` bounce，
  先整段读一遍算 CRC32/SHA-256，再按 1 MiB 流；小分区仍 16 KiB。`/status` 报 `backup=idle|active`、`backup_part`。
- **`/reboot`**：空 body + `X-E2631-Confirm: reboot`（缺失/不符 400 `missing confirm`）；任一写任务或备份流期间 409；
  应答 `result=accepted`/`reboot=1` 后等 TCP `DATA_SENT`，救援循环里再等约 300 ms（上限 3 s）调 0029 的
  TOPCRM 软复位；串口打印 `resetting ...`。`/status` 增 `reboot_pending`。
- **蓝灯**：GPIO0 bit8（`0x94407000` DIR / `0x94407014` DATA，active-low）。进入救援保存 bank0 DIR/DATA，
  只把 bit8 改输出并 1 Hz 翻转；退出/Ctrl-C/错误/复位前恢复 bit8 原值（其它位不动）；不驱动绿/红。
- **DHCP 配置**：`e2631_dhcp_ipaddr`（默认 192.168.1.1）、`e2631_dhcp_netmask`（默认 255.255.255.0）、
  `e2631_dhcp_pool_start`（默认 100，1..254）、`e2631_dhcp_pool_size`（默认 101，1..200）；优先级
  `e2631_dhcp_*` > 旧 `dhcpd_pool_start/size` > 内置默认；服务器地址/掩码不再从 `ipaddr`/`netmask` 取。
  非法值回落默认并在 `/status` 报 `dhcp_source=fallback` + `dhcp_warning`（逗号列表）；池终点 ≤ .254 且池不能包含
  服务器地址；`POST /env` 对这四个键做同样的语义校验（非法 400 `bad value`）。配置只在 `e2631rescue` 启动时读一次。

## 9. task-93 后修复：DHCP 池误报（patch 0052）

### 9.1 现象与根因

verify-docs 的 task-93 Phase A（设备、零写入，v3 构建 `banner g2bd1efb71eb1`）在**干净 env**（26 个厂商键，无
`e2631_dhcp_*`）上看到 `/status` 输出：

```
dhcp_source=fallback
dhcp_warning=e2631_dhcp_pool_start
```

串口同步打印 `pool 100..200 (fallback)`；DHCP 仍可工作，但页面/脚本会误以为配置非法。根因在
`rescue_dhcp_load()`：

```c
host = rescue_dhcp.ip.s_addr & 0xff;
```

`struct in_addr` 按网络字节序存放地址；在小端机上 `192.168.1.1` 的内存字是 `0x0101a8c0`，`& 0xff` 得到的是
**第一字节 192**，不是主机八位组 1。192 落在默认池 100..200 内，于是被判成“池包含服务器地址”，触发 fallback。
Linux 侧 `e2631_dhcp_*` 默认值本身没问题（服务器 192.168.1.1、池 100..200），不需要改页面。
