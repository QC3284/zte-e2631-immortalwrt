## 3. 上游架构对照

- 上游 web console 不是 telnet 隧道：它用 U-Boot console record 提供 `/console/exec`、`/console/poll`、
  `/console/abort`、`/console/clear` 四个 JSON 端点，telnetd 是独立 RFC-854 服务；两者只共享一个执行槽。
  本实现照此结构落地，未做 HTTP↔telnet 的字面桥。
- 上游用 `mtk_tcp_abort_request()` 让 Ctrl-C 中断执行中的命令：本树补了 `net/net.c` 主循环钩子
  （`mtk_tcp_periodic_check()` + abort 消费），telnetd 与 web console 的 abort 走同一条路径。
- 上游在网络命令结束后置 `eth_needs_reinit`，在主 poll loop（非回调链内）重入 eth_init 并重注册 DHCP/DNS；
  本实现以 `webconsole_net_reinit` 做同样的事，避免在 TCP 回调里递归。
- 端口：web 80（v1 起）、DHCP 67、DNS 53、telnet 23（`telnet_port` 可改）。页面侧由 task-91/task-96 提供，
  消费 v3 契约端点 + 这四个 console 端点；页面未改动。

## 5. UDP 魔法包触发：technically deferred 的论证

事实：

1. 本 U-Boot 的 autoboot 窗口是 `CONFIG_BOOTDELAY=3`，而 `eth_init()`/PHY 自协商在救援命令或 e2631boot
   里才发生；窗口内没有可接收的 UDP 监听点。
2. 要支持“魔术包打断启动”，必须在 autoboot 之前提前初始化以太网并驻留收包，等于把每次开机都变成
   “先起网络”：与既有 bootdelay=3 的口径冲突，并显著增加正常启动时间；同时会改变 P2 阶段已验证的
   启动时序（C1b/A5 的回归面）。
3. 唯一固定的是“按键进救援”，其它进入方式可改/可加；因此不采用“为了兼容按键而不做”的理由，
   而是给出上述技术结论：需要先决定窗口策略（例如只在按键已触发后监听、或接受延迟），本轮不具备条件。

后续若要支持，建议先做零写入 RAM 链实验测量 eth 初始化对启动时间的影响，再谈是否改 bootdelay 策略。

## 6. t92c 两个 /env 缺陷

- 缺陷 1（genuine no-change 写 403）：候选块用 RAM env 构建，含 `fdtcontroladdr` 与 `serial@...` 的
  `stderr/stdin/stdout` 运行时键；对比逻辑把它们当“要持久化的变化”并撞上厂商白名单。修复 0058 在对比前
  按 flash 基线对齐（写后恢复 RAM），no-change 请求返回 200 `result=ok keys=0`。
- 缺陷 2（池边界 403 而非 400）：`/env` 的语义检查原先只独立检查 pool_start 1..254 / pool_size 1..200，
  没有检查池与服务器地址的冲突；修复 0059 复用 0052 的共享 helper，冲突/越界返回 400 `bad value`。
- 精确串口证据：`evidence/e4-v3-phasea-t92c/serial-env-excerpt.txt`（当前 env 26 entries CRC 0xf95a816e，
  candidate 27/28 entries，两次都停在 `e2631_env_write_begin` 之前，未擦写）。

## 10. 风险与边界

- 救援服务无鉴权（用户裁决）：只在 lan1 监听，页面无口令门；不要把 lan1 接到不可信网络。telnetd 不提供
  stdin 会话隔离；`failsafe_console_token` 只保护 web console 的 exec 端点，不保护 telnet 端口。
- console 命令同步执行：长命令会阻塞 DHCP/HTTP 响应；页面用 busy/abort，串口用户需知悉。
- telnet/DNS 启动失败只 WARNING，救援 HTTP 不依赖它们；回滚只需去掉 rescue_loop 里的 start 调用。
- 尺寸：0055-0059 的实际增量以 task-92 构建为准；不得以放宽硬上限解决。
- 页面未改动：页面侧任务（task-91/task-96）已消费 v3 契约；本批只在 C 侧补齐四个 console 端点，
  未改页面协议。
