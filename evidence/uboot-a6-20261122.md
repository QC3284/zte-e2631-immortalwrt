# A6：PCIe 端点复位/供电线（patch 0013）构建与零写入验收

日期：2026-11-22。范围：E2631 板级 U-Boot；本记录不含任何 flash/env 写入。

## 1. 背景

A5（patch 0012）修复了 flash 链的网络参考时钟/SerDes 后，eth 恢复（PHY 10-13、link up、flow offload），
但 PCIe 仍只有两个 root port（`1cf2:6830`），没有 endpoint；`14c3:7906`/`14c3:790a` 不出现，
`mt7915e` 不绑定，`e2631-wifi-boot` 以 `mt7916 init failed` 结束；rescan 也找不到设备。
verify-docs 的两链 post 对比（我们 vs 厂商 U-Boot）只剩 10 个寄存器字不同：`0x94400018`（LSP0 SPI
时钟寄存器，内核 clk 驱动会配置）、`0x94407014`/`0x944070d4` 的 bit2/bit3（GPIO pin 2 / pin 51）、
以及 `0x9A101004/8/14/18/1c`（MDIO 控制器内部，内核驱动重新初始化）。前两项与 PCIe 无关；剩下的
bootloader 侧状态只有 pin 2 与 pin 51。

## 2. 根因（厂商逆向）

`zte_gpio_init()`（`0x47f2f314`）在板级表回放后还有两段循环：

- `0x47f2f61c`–`0x47f2f668`：再次遍历 52 项板级表，`index == 0x33`(51) 且 `dir == 1`（输出）时调用
  `gpio_set(pin, 1)`；表索引 51 是 pin 2；
- `0x47f2f66c`–`0x47f2f6c0`：同样遍历，`index == 0x32`(50)，表索引 50 是 pin 51。

两项在板级表里都是 `en=1 / dir=1 / val=0`，即厂商特意用尾部特例覆盖表值、把两根线驱高。
厂商 payload 全文扫描显示它对 PCIe host/PHY/ctrl/config（`0xf000000`、`0xf100000`、`0x9500000`、
`0x9600000`、`0x1c000000`、`0x2c000000`）零访问，因此这两根 GPIO 是 bootloader 侧唯一可能影响
PCIe 端点可达性的状态。工作假设：pin 2 / pin 51 是两个 endpoint 的复位/供电使能。

## 3. 修复（patch 0013）

`board/zte/zxhn-e2631/e2631net.c`：

- 新增 `E2631_GPIO_PCIE_RST0 = 2`、`E2631_GPIO_PCIE_RST1 = 51`；
- 在 `e2631_pinmux_gpio_init()` 的板级表输出回放之后先驱 pin 2，`mdelay(4)`，再驱 pin 51
  （与厂商 loop A / loop B 之间的 4 ms 一致）；
- SET 位 RMW，幂等；`e2631boot` 与 `e2631refclk` 共用同一路径（0012 的调用点）。

设计、证据与回退见 [../uboot-port/a6-pcie-endpoint-reset-design.md](../uboot-port/a6-pcie-endpoint-reset-design.md)。

## 5. A6 零写入真机验收（待 verify-docs 执行）

1. 厂商控制台 → `loadx`/`tftp` 把 `u-boot.bin` 装到 `0x47F00000`（sha256 先核对）→ `go 0x47F00000`；
2. banner 应为 `g6620d6e97d78`；
3. 可选 `e2631refclk`：契约不变（7 个寄存器、before/after 各两行）；
4. **`e2631boot` 之前**：`md.l 0x94407014 1` 的 bit2 必须为 1、`md.l 0x944070d4 1` 的 bit3 必须为 1
   （A5 run-3 时均为 0）；
5. `e2631boot` → 内核启动；验收签名：`lspci` 出现 `14c3:7906`（bus0）与 `14c3:790a`（bus1）、
   `mt7915e` 绑定、`e2631-wifi-boot` 完成且不再出现 `previous initialization unfinished` /
   `mt7916 init failed`；eth 项保持（PHY 10-13、link up）；
6. 全程不写 flash/env；结束后核对 mtd0 sha256 不变。

## 6. 风险与回退

- pin 2 / pin 51 的功能无硬件文档，复位/供电是工作假设；若 PCIe 仍失败，下一步需要复位时序/供电
  细节（可能要在拉高前后加延时或调整顺序）。
- 若这两根线影响其它外设：删掉 `e2631net.c` 末尾两行 `e2631_gpio_drive()` 即回到 A5 状态。
- 补丁只影响 E2631 板型，不改 0001–0012，也不碰 SoC 通用代码。
