> 结论：树 fork 不需要改；kit 的 U-Boot 移植新增 patch 0010，把 `CONFIG_TEXT_BASE`
> 从 `0x43000000` 改为 `0x47F00000`（secondboot 的固定入口）。CI 重建绿，
> 新产物 `e2631-uboot-44898534408`，banner 令牌 `g2797f3dd3860`，

> 全程未接触设备，未写 flash。

## 1. 背景与根因

- 产品链：secondboot 校验/解包后把 U-Boot 载荷 `memcpy` 到 `0x47F00000`，再用
  `blx` 跳入（逆向证据 [uboot-re-20261115.md](uboot-re-20261115.md) §4：
  `00205930 ldr r6, [pc, #0x5c] ; r6 = 0x47F00000`、`0020595c blx r6`）。
- 我们的 A1 移植此前链接在 `0x43000000`（为厂商控制台 `tftp 0x43000000` + `go` 的
  RAM 链服务）。入口与链接地址不一致时**不会**因为“位置无关”而工作：
  - `CONFIG_POSITION_INDEPENDENT` 未开（`.config` 第 48 行），`start.S` 的
    `pie_fixup` 不编译；
  - `arch/arm/lib/relocate.S` 的修正量 `r4 = gd->relocaddr - run_image_start` 假设
    运行地址 == 链接地址；错位进入时每个 `.rel.dyn` 绝对量都会差 `0x4F00000`；
  - `board_init_f` 用的 `INITCALL()` 是直接调用（不是函数指针表），但
    `.rodata`/`.data` 的常量、BSS 清零地址、向量表基址仍按链接地址编译。
  - 结论：从 `0x47F00000` 进入旧镜像会在 banner 之前挂死或 data abort。

## 5. 布局自查（来自本产物的 `u-boot.map`）

| 符号 | 值 |
| --- | --- |
| `__image_copy_start` | `0x47f00000` |
| `__image_copy_end` | `0x47f62098` |
| `_end`（含 `.rel.dyn`） | `0x47f6d670` |
| `__bss_start` / `__bss_end` | `0x47f62098` / `0x47f6b764` |
| 初始栈 `CONFIG_CUSTOM_SYS_INIT_SP_ADDR` | `0x48000000` |

- 载荷（含 `.rel.dyn`）结束于 `0x47f6d670`，到初始栈底 `0x48000000` 有
  **600,464 B（`0x92990`）** 空隙；early malloc + `gd` 位于栈下方约
  `0x47fff7d0..0x48000000`，不压到镜像。
- 重定位目标与运行栈由 DRAM 顶（`0x50000000`）向下计算，与 `TEXT_BASE` 无关；
  BSS 在重定位后的副本上清零，不与 load 区冲突。
- mtd0 封装：payload 起 `0x20800`、末 `0x6d670`（< `0x9F800` 上限，也 < env `0xC0000`）。

## 6. C1b-0 验收步骤（零写入，需 Lead/用户批准会话）

1. 厂商 U-Boot 控制台（串口 115200）：`tftp 0x47F00000 u-boot.bin`
   （文件 = 本产物的 `u-boot.bin`，448,112 B，先核对 sha256）。
2. `go 0x47F00000`。
3. 预期：banner `U-Boot 2027.01-rc2-g2797f3dd3860`；
   `Loading Environment from MTD... OK`；3 s 后 autoboot 执行 `e2631boot`；
   slot1 选中并 `bootm` 进 Linux（无 data abort）。
4. 全程只读；失败断电恢复（vendor chain 不动，mtd0 不写）。
5. 串口日志落盘到 evidence/ 并汇报。

## 7. 风险与边界

- 入口固定 `0x47F00000`（secondboot 硬编码）。本移植非 PIE，入口必须等于
  `TEXT_BASE`；若后续 secondboot 行为变化需重新逆向。
- 厂商控制台 `tftp 0x47F00000` 依赖“厂商 U-Boot 已自重定位到 DRAM 顶部”的
  标准行为；会话里可用 `bdinfo` 的 relocation offset 佐证。
- 本次不改源码、不改 `.rel.dyn`/重定位逻辑，唯一行为变化是链接地址。
- 未写 flash、未写 env、未接触设备。
