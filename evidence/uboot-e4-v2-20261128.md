## 2. 实现要点

### 2.1 槽位与固件包（0036）

- slot0 0x00700000、slot1 0x02300000，跨度 0x01C00000；版本头在槽内 +0x1500000。
- 包上限 `E2631_PKG_BODY_MAX + 0x214` = 0x1BE0214；校验顺序 14 项（包长/magic/头 CRC 1+2/
  product `ZXHN E2631 V1.0.0`/boot_included=0/body size/槽基址/内核与 rootfs 区间/两段 CRC/坏块/SHA-256）。
- 守卫：目标槽是 intact 的厂商镜像才拒绝（`refusing to overwrite a working vendor system`）；另一槽
  可验证时 weak，不可验证/不完整时拒绝；auto 且无 next_slot 拒绝。
- 写：擦整个目标槽（跳坏块，保留其它槽）→ body 按 128 KiB 块写（尾块补 0xFF）→ 下一个好块写 512 B
  版本头（H_SLOT_START/H_SERIAL=max+1/H_NEW=1/H_CRC2 重算）→ 回读 slot_scan + slot_verify；失败擦掉
  目标槽版本头并报 `verify failed, header erased`。

### 2.2 恢复出厂（0037）

- 只擦 `rootfs_data`（mtd 偏移 0x03360000、长 0x004A0000），擦完做全 0xFF 校验；两段都按擦除块对齐
  并有 static_assert。
- 必须按名字找到 `rootfs_data` 并核对 offset/size，不匹配即 `layout mismatch`（防止误擦）。
- 状态机 erase→blank→done，progress 10/60/100；不触碰 userdata、slot、bootloader、env。

### 2.3 一次性启动槽（0037）

- `e2631boot` 选槽后读 RAM env 键 `e2631_next_slot`（仅 "0"/"1"），目标槽有有效头且不同于当前槽时
  本次启动改用它；只影响本次启动，不写 env/flash，失败自动回退到扫描结果。

### 2.4 env 写回（0038）

- 白名单仍是 `e2631_*` + `bootdelay`；`/env` 端点由 e2631rescue 校验后调用 e2631env 的分阶段写。
- 五步写不变：坏块预检→擦→读回全 FF→写→读回逐字节比较；vendor 快照/保留扇区检查仍在。
- `/status` 用 op=envwrite + stage diff/check/erase/write/readback/verify/done 呈现进度；无变化返回
  result=ok keys=0（页面不会走到这条路径，属防御分支）。

### 2.5 HTTP 端点（0039）

| 方法/路径 | 行为 |
| --- | --- |
| GET / | 内置 gzip 救援页（Content-Encoding: gzip） |
| GET /status | v1 键保持不变；v2 追加 op/mode/slot/slot_target/slot_target_identity/guard/guard_reason/bytes_total/bytes_done/written_serial/version/next_slot/next_reason/slot0_*/slot1_*/slot1_header_partition/bootloader_region_crc32 |
| GET /slots | 两槽有效/完整/身份/serial/版本/header_at，span 0x1C00000，slot0=mtd5、slot1=mtd6 |
| GET /env | 只读 key=value 列表 |
| GET /backup?part=bootloader|tag|wifi|usercfg|defcfg | raw + X-E2631-CRC32/SHA256/Offset/Length/Part；16 KiB 流式；只读；默认 bootloader |
| POST /flash | v1 保留：655360 B 整 mtd0 镜像 → 0x20000..0xC0000 五步写 |
| POST /firmware?mode=validate|write&slot=auto|0|1 | validate 同步 14 项校验 + 守卫；write 需 X-E2631-SHA256 + X-E2631-Confirm: write，返回 accepted 后状态机推进 |
| POST /boot?slot=0|1 | 只写 RAM env `e2631_next_slot`，仅本次启动 |
| POST /factory?confirm=reset | 恢复出厂（只擦 rootfs_data），需 X-E2631-Confirm: reset |
| POST /console?cmd= | 单条命令，4 KiB 尾部输出捕获，换行/反斜杠转义；无 stdin、无口令门 |
| POST /env?key=&value=&confirm=write | 单键白名单写，需 X-E2631-Confirm: write，复用 e2631env 五步 |

- 单飞行：忙时 409 busy；错误 400/409/500 + `result=error` 与短 ASCII `error=`。
- 写路径 owner 不变；板级源码扫描只允许四个写者文件出现 mtd_write/mtd_erase/mtd_special_write_oob。

### 2.6 内存与分区

- 固件暂存区 0x46100000，上限 `E2631_FW_STAGE_MAX=0x1C00000`（包上限 0x1BE0214）；
  static_assert 保证 ≥0x46100000、+MAX ≤0x47F00000、>CONFIG_SYS_LOAD_ADDR、≥DMA arena 末端。
- 现有布局：staging 0x42000000、bounce 0x44000000、DMA arena 0x45000000..0x45FFFFFF、救援页上传
  0x46000000（1 MiB）、固件暂存 0x46100000..0x47CFFFFF；U-Boot 自身链接在 0x47F00000，互不重叠。

## 7. 风险与边界

- 救援页无鉴权、控制台无口令门（用户裁决：功能优先，风险只写文档）：任何能连上 lan1 的人可执行
  `/console` 与白名单 env 写；因此救援期间应只接可信网络，用完断电。
- `/console` 在命令执行期间阻塞 HTTP 循环（命令是同步 run_command）；长时间命令会让页面轮询超时，
  文档已写明。
- 尺寸余量只有 2,192 B（405,368 / 407,560）；后续加功能必须先调预算并说明理由。
- 单飞行：web 服务同一时刻只接受一个长任务，忙时其它写/读端点返回 409。
- slot 写失败会擦掉目标槽版本头（安全但需重传）；本记录未在真机写入。
