  （`0x3F00000`，约 49 MiB）可写且未使用 → `e2631flash` 必须支持 flash 偏移源：先读入 1 MiB
  bounce buffer（`0x44000000`）再擦写。

三条 `U_BOOT_CMD` 的 usage 原文（pkg-release 门禁用）：

- `e2631flash`：`flash an image to SPI-NAND with erase, blank and readback checks`
- `e2631verify`：`compare a RAM image with a SPI-NAND range by CRC32 (read-only)`
- `e2631slot`：`print the firmware slot table`

`e2631flash` 源语义：`<src> >= 0x40000000` 为 RAM 地址；`<src> < 0x10000000` 为 NAND 字节偏移，整段
先读入 `0x44000000` 的 1 MiB bounce buffer；长度上限 1 MiB；拒绝未对齐、越界、secondboot
（`0x00000..0x20000`）、env（`0xC0000..0xE0000`）。擦除前打印 `DO NOT POWER OFF DURING WRITE`；
擦除→全 FF 校验→写入→读回逐字节比较；打印 staged payload CRC32、readback CRC32、PASS/FAIL 与首个
不一致偏移。

## 5. 真机零写入验收（下一次会话，需用户批准；不写 flash）

装入方式同既有 RAM 链（厂商控制台 `tftp 0x47F00000 u-boot.bin` + `go 0x47F00000`），或从已安装的
flash U-Boot 中断 autoboot 停在提示符。**只跑只读/拒绝路径**：

1. `e2631slot`：两个槽的 base/span/serial/version 与 `cspboot would boot slotN` 应与 C1a 记录一致。
2. `e2631verify <ram地址> <off> <len>`：对已知 RAM 镜像做只读 CRC32；故意改一个字节应 FAIL。
3. `e2631flash` 拒绝路径（都在擦除前返回，零写入）：未对齐 `off`/`len`、长度 >1 MiB、secondboot 区、
   env 区（`0xc0000`）、越界（`off+len > 0x8000000`）、`<src>` 落在 `0x10000000..0x3FFFFFFF`。
4. 记录每次拒绝的输出与 mtd0（`0x00000..0x100000`）sha256 不变，作为“拒绝路径不写 flash”的证据。

## 6. 真机写入会话（单独批准，不在本轮）

1. Linux 侧把新 mtd0 镜像写入 userdata（`/dev/mtd10`，U-Boot 偏移 `0x3F00000`），记录主机 CRC32/sha256。
2. 重启进本 U-Boot；`e2631flash 3f00000 20000 a0000`：先打印 `DO NOT POWER OFF` 与 staged payload
   CRC32，**核对 CRC 后再让它继续**；随后擦除→FF 校验→写入→读回比较，打印 readback CRC32 与 PASS。
3. 写前、写后各记录 mtd0 `0x00000..0x100000` sha256；断电重启确认 banner/`e2631boot`/内核/PCIe/WiFi。
4. 任何一步失败：不重启、不断电，按 rescue 文档走串口恢复。

## 7. 风险与边界

- 写 mtd0 U-Boot 区掉电会半写 → 只能串口救砖；先零写入核对 CRC、单独一次写入、写前写后 sha256 留档。
- `e2631verify` 仍只接受 RAM 源（flash→flash 只读比较当前由 `e2631flash` 的 staged payload CRC32 承担）。
- bounce buffer 固定 `0x44000000`（1 MiB），避开内核 load `0x40008000`、uImage 暂存 `0x42000000` 与
  重定位后的 U-Boot；不做动态分配。
- autoboot 流程不调用 `e2631flash`；回退 = 删掉命令注册，不影响 0001-0013 的启动路径。
