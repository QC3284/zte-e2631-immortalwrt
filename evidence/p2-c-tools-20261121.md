### 1.3 控制台密码 patch（仅离线演练）

~~~

~~~

- 写入位置：mtd0 + 0x61F80，20 B 无盐 SHA1

- 0x61F94 的 enable flag 保持不变

- 注：本次只对 dump 副本演练，未写设备；密码长度上限 16 B 是保守假设（vendor 只留了 "passwd is too long" 字符串，实际截断长度未测）

### 1.4 回读校验

~~~
node tools/verify-mtd0.mjs --file <dump> --sha256 de4ea5bd...
node tools/verify-mtd0.mjs --file <篡改副本> --baseline <dump>
~~~

- sha256 模式：匹配输出 OK，不匹配 exit 1

- 单字节篡改（0x61F80+5）被报告为 1 个区间、精确偏移

## 2. 2026-11-20 编程器 dump 交叉验收

两个整片 dump 与现网 mtd0 的关系本轮用工具/测试固化，均通过：

| 输入 | 大小 | 交叉结论 |
| --- | --- | --- |
| zxhn_e2631_full-v2-ECC.bin | 134217728 B（128 MiB） | 数据区镜像；前 1 MiB 与现网 mtd0 dump **逐字节相同** |
| zxhn_e2631_full-v2-RAW.bin | 138412032 B（132 MiB） | 2112 B 页（2048 数据 + 64 OOB）；前 512 页数据解交织后与现网 mtd0 **逐字节相同**；每页 OOB **全 0xFF** |

意义：mtd0 在整片镜像中的偏移确定（0x0，数据区直读即可）；v2 RAW 的 OOB 全 FF 再次确认「编程器没导出 ECC 位」，写回 ECC 方案仍未验证（风险 R1/R2 不变）。

## 4. 工具接口（给后续任务）

~~~
mkuboot-image.mjs unpack --dump <mtd0> --payload <out> [--header <out>] [--tail <out>] [--json]
mkuboot-image.mjs build  --dump <template-mtd0> --payload <file> --out <region.bin>
                         [--tail <file>] [--full-mtd0 <out>] [--json]
mkuboot-image.mjs check  --dump <mtd0>

e2631-env.mjs dump   --dump <mtd0> [--out <text>] [--json] [--allow-bad]
e2631-env.mjs build  --in <text> --out <env-block.bin> [--template <mtd0> --full-mtd0 <out>]
e2631-env.mjs verify --dump <mtd0>
e2631-env.mjs check  --dump <mtd0>

patch-uboot.mjs password --in <mtd0|-> --password <new> --out <mtd0> [--print] [--json]
patch-uboot.mjs check-password --in <mtd0> --password <candidate>

verify-mtd0.mjs --file <dump> [--sha256 <hex>] [--baseline <dump>] [--offset <hex>] [--length <hex>] [--json]
~~~

约定：

- 输入/输出都是普通文件；patch-uboot 的 --in 支持 "-" 从 stdin 读，便于串口/管道场景
- 镜像区固定 mtd0 0x20000..0xC0000；0x800 头块从模板 dump 逐字节复制，只改 +0x14；0x2D4 摘要原样保留
- payload 上限 0x9F800（0x20800 + 0x9F800 = 0xC0000，刚好停在 env 之前）；超限报错
- env 区块固定 [u32 LE CRC32][0x1FFFC 数据]，CRC32 与 U-Boot 2013.04 / 主线 env 相同
- 密码 patch 只写 0x61F80..0x61F93 共 20 B，flag 0x61F94 不动

## 5. 对上一轮文档的一处修正

evidence/p2-uboot-research-20261121.md 初稿把「载荷末 ≤ 0xA0000」写错了。RE §8.3 的准确约束是：

0x20800 + payload_len <= 0xC0000（不得侵入 env），即 payload_len <= 0x9F800，载荷末可到 0xC0000，而不是 0xA0000。

本轮已在 p2-uboot-research-20261121.md 修正 3 处（§0.3 U-Boot 区范围、§1.1 布局表该行说明、§4.1/§4.2 工具与格式表中 0xA0000 -> 0xC0000），并在本文 §4 固化。工具实现按修正后的边界：region 大小 0xA0000（0x20000..0xC0000），payload 上限 0x9F800。

## 6. 未做 / 限制（诚实清单）

1. 未连设备：没有写 mtd0、没有读 OOB、没有验证 vendor nand write.uboot 语义（P1 OOB 取证仍待用户批准）。

4. 检查器 tools/check-workflows.mjs 未新增断言（94 项保持不变）；新工具由 make check 的离线测试覆盖，避免动网络门禁。
