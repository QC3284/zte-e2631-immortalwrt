# A5：网络参考时钟 / SerDes / 管脚上电状态重放（patch 0012）

## 0. 结论

- C1b-1（0011）让 flash 链的内核能启动，但网络缺口还在：MDIO 总线时钟在走（`mdio_wclk` 50 MHz），
  四个内部 PHY（地址 10-13）无应答，两个 PCIe 根端口只有 `[1cf2:6830]`、没有端点。
- 根因：厂商 U-Boot 的板级上电序列（`board_eth_init()` `0x47f00850` + `zte_gpio_init()` `0x47f2f314`）
  在这条链上从未执行；内核 clk 驱动（`clk-zx279128s.c:8-10`）明确假设 bootloader 已完成网络 PLL/SerDes，
  且没有内核驱动碰 `0x94000008/0x50/0x54`、`0x94100010`、`0x9FE00000`、`0x9A107008`、`0x9A100004`。
- 交付：patch 0012（12 patch 系列，post-am tree `3f1eeb4941ada08255f7bd4b5c936d6a1a3750f4`，
  patch sha256 `9c075c60f5cd6282e8b507d7ee0e02b4fc68544d0f55f4d1b4c43a8f187ed87b`）。
- 寄存器集按 verify-docs 的两链 pre/post md dump（62 个不同 32 位字）裁剪，只保留值确实不同或 pre 不可读的项。
- uboot-build CI run `44929440623` SUCCESS（bit26 修正后重编，见 §4.1；数值见 §4）。真机 A5 会话（零写入）尚未执行，签名见 §6。

## 3. patch 0012 内容

文件（4 个，+316 行）：`board/zte/zxhn-e2631/e2631net.c`（290）、`e2631net.h`（14）、`e2631boot.c`（+11，
`if (load)` 时在 `mtd_probe_devices()` 之前调用 `e2631_net_refclk_init()`）、`Makefile`（+1）。

顺序（与厂商一致）：

1. `zte_gpio_init` 的 pinmux：先 `[0] |= 0xC00`、`[+4] |= 0xC0`、`[+0xC] |= 0x00180E80`，再写入板级表六个整字
   `0x0f3ffffa`、`0x00effeff`、`0x0555ffff`、`0x003dbf85`、`0`、`0`；只驱动 8 个输出
   （8=1、40=1、60=0、55=0、52=0、54=0、51=0、2=0；板级表值）。
2. 分数 PLL：`0x94000050` bit31=1 / bit27=0 / bit24=0 / bits[23:18]=1 / FBDIV 0x5D / PD1 5 / PD2 3；
   `0x94000054` 清 bit27、置 bit26、清 bit25/bit24，再写 `(当前值 & 0xFF000000) | 0x004FDF3B`（保留高字节，
   使 bit26 留下）；`mdelay(100)`；清 bit31；`mdelay(50)`。
3. `0x94000008` 清 bit5+bit4，delay，置 bit5，delay。
4. `0x9FE00000` 24 个字（`+0x40` 写两次：`0x003c0000` 后 `0x003c0040`）；`0x94000008` 置 bit4。
5. `0x94100010` 清 bit11、`bits[9:6] = (0x9A107008 >> 24) & 0xF`。
6. `0x9400004C` `bits[8:0] = 0x1FF`；`mdelay(200)`；`0x9A100004 = 0x0001381B`；`mdelay(200)`。
7. `0x9400000C` 清 `bits[21:20]`、置 bit20（厂商以太网 probe）。

`e2631refclk` 命令跑同一函数，打印 7 个寄存器（`0x94000050/54`、`0x94000008`、`0x94100010`、
`0x9400004C`、`0x9A100004`、`0x9400000C`）的 before/after 两行后返回提示符，不启动、不写 flash/env；
自动路径（`e2631boot`）打印前四行（两组 before/after）后继续启动。两条路径是同一个函数，幂等。

### 4.1 bit26 修正（v1 -> v2）

- 复查厂商 `pll_cfg_fractional`（`0x47f2f8bc`）发现 `0x94000054` 的完整序列：清 bit27、置 bit26、清 bit25、
  清 bit24，然后 `0x94000054 = (当前值 & 0xFF000000) | 0x004FDF3B`；最后一次写保留高字节，所以 bit26
  （分数 PLL 使能位）必须由前面的步骤置上。
- 初版重放只做了一次 `(pre & 0xFF000000) | FRAC`，而本链 pre 高字节为 `0x00` -> bit26 丢失，分数 PLL 使能
  停在复位值；厂商 md 末态 `0x144FDF3B` = bit28（锁/状态）+ bit26 + FRAC。
- 修正后 `e2631refclk` 的 after `PLL1` 应为 `0x044FDF3B`（若 bit28 已由硬件置位则 `0x144FDF3B`）；
  其余寄存器重放不变。patch sha256 -> `9c075c60...`，tree -> `3f1eeb49...`。

## 6. A5 真机会话（需用户批准；零 flash 写入）

1. 从当前系统 `reboot -f` 进入我们的 flash U-Boot 提示符（不要执行任何写命令）。
2. `md 0x94000000 0x40`、`md 0x94100000 0x10`、`md 0x94200000 0x10`、`md 0x94407000 0x40`、
   `md 0x9a100000 0x10`、`md 0x9a101000 0x8` 记录 pre 状态（`0x9fe00000` 此时应不可读，不要读）。
3. `e2631refclk`：记下两行 before / 两行 after（7 个寄存器），确认与 §3 的目标值一致；
   after 的 `0x9400000C` 末四位应为 `...7800`（bit20 置位）；`PLL1` 应为 `0x044FDF3B` 或 `0x144FDF3B`
   （bit28 是锁/状态位，硬件可能自行置位）。
4. `e2631boot`（会再跑一遍同一函数，幂等）→ 内核启动。
5. 内核签名：`mdio_bus` 出现 PHY 10-13 且 link up（`lan1`/`wan` 1 Gbps）；`lspci` 出现 `14c3:7906`（bus0）
   与 `14c3:790a`（bus1）；日志出现 `MT7916 ready`/双频可转发；`pll_lsp` ≈ 1 GHz、`mdio_wclk` 2.5 MHz。
6. 会话结束核对 `mtd0` sha256 与进入前一致（应仍为 `887a7f6c9b407abc734eb9a76f08733a691441f91987369e8626deb8faf0fa9f`），
   全程无 flash/env 写。

## 7. 风险与未决

- `0x9400000C` 的写入来自厂商以太网 probe（`board_eth_init` 之后），不是 board_eth_init 本身；两链 dump 证明它
  确实不同，故纳入。若 A5 出现异常，先回退这 3 行 RMW（`e2631net.c` 末尾）观察。
- `0x94100024` 未 dump；`0x94400018` bit11 的变化归属未定位；MDIO 控制器内部寄存器交给内核——三者都不在 0012。
- 厂商提示符处 pin2/pin51 为高，但板级表值为 0（板 init 之后被 cspboot 驱动）；0012 按表值写 0，A5 记录实际电平。
- 0012 不做网络协议栈、PCIe host、PHY 驱动；不碰 PL310/SCU/ACTLR（厂商也不碰）。
- 回退：删掉 `e2631boot.c` 里的 `if (load) e2631_net_refclk_init();`（或整 patch），启动链其余部分不依赖。
- 只作用于 E2631 板型，不碰 SoC 通用代码。
