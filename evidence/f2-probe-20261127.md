## 4. 两处修正

### 4.1 0x003883c0 不是 SBRG 寄存器

patch 0031 中 zx_cmd_sbrg 使用 priv->base；uboot dts 的以太网节点是 ethernet@92000000，所以 SBRG 寄存器地址是 0x92000000 + 0x3883c0 = 0x95883c0，而不是 0x003883c0。会话里 md.l 0x003883c0 读到的 0 属于无关低地址，不能作为 egress mask 基线；e2631net sbrg / e2631net 打印出来的 0xfe... 才是真实值。后续探针若需要原始寄存器，应读 0x95883c0 起的 5 个 word。

### 4.2 e2631net sbrg 输出契约与交接不一致

patch 0031 的 zx_cmd_sbrg 在不带 allow 时只调用 zx_sbrg_vlan_dump，打印 “SBRG VLAN 1 words ...”；learn / port ctrl / egress 只在 e2631net 或 e2631net tx 的输出中出现，egress before/after 只在 allow 分支打印。交接时描述的 “sbrg 打印 learn / port ctrl / egress 掩码和 VLAN1” 与实际代码不符，需要 base-builder 在下一版修正代码或说明。

### 4.3 TM status 的读清语义

第一次发送后命令行里打印的 TM status 是 0x00003200；随后 md.l 读取为 0。这是读清行为，不应把后续的 0 解释为“从未有事件”。判断需要结合 e2631net tx 命令自身打印的 TM status 与 tx done。

## 5. 判读

1. 四种发送模式（两种描述符队列、两种 word3 配置）结果完全一致：没有 MAC TX 帧、没有网线帧。描述符变体不足以解释失败，C1 从“唯一原因”降级。
2. CPU egress mask 为复位值且 allow 不改变它：C2 排除。
3. SBRG VLAN1 三个 word 全 0，是当前最显眼的未排除候选（C3）。需要判断 VLAN1 是否必须写有效位/成员位，以及桥在入口是否因 VLAN 无效而丢帧。
4. hw tx idx 从 0 到 0 从未前进，而驱动认为前 10 次发送成功；第 11 次开始出现 TX completion timed out，tx done 以读清方式出现 0x00010000 / 0x00020000。这与“描述符 word0 不是 DRAM 地址而是 BMU block index、block→DRAM base 映射未编程”的新方向一致：ring 的取指/所有权没有前进，超时只是环被复用后的结果。该解释是假设，最终由 base-builder 的下一版探针验证。
5. 其他原始值供后续对照：MAC ctrl 0x00bb2003，dma ctrl 0x003f6564，ring cfg 0x00400040，tx ring 0x45c00000，BMU free 0x70000111，TM ctrl 0x140，SBRG learn 0x00000000，port ctrl 0x000200ff，SPA port en 全 1，SW fwd 0x00020000。
