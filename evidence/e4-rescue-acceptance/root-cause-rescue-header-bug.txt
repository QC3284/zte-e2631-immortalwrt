Why every POST hits "unsupported request":

rescue_name_is() lowercases the bytes of the *received* header line, but
compares them against the caller-supplied *name* unchanged.  Every caller
passes a mixed-case literal ("Content-Length", "X-E2631-SHA256",
"X-E2631-Confirm", "X-File-Sha256").  rescue_lower('C') == 'c' != 'C', so
the comparison can never be true for the first character.  rescue_header_value()
therefore returns false for Content-Length, rescue_handle_request() jumps to
bad:, and the server replies "HTTP/1.1 400 Bad Request / result=error /
error=unsupported request" before reading the body.  GET requests do not use
rescue_header_value(), which is why GET / and GET /status work.

Fix: compare rescue_lower(line[i]) with rescue_lower(name[i]) (or pass
lowercase literals).  This blocks both mode=validate and mode=write until
a patch fixes it; the write path has never been testable.
